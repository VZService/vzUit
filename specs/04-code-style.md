# 04 · 代码风格

## 文件与目录

文件名一律 kebab-case 小写英文，不用中文、不用空格、不加日期或版本后缀。目录名同规则。禁止出现「XX版」「新版」「旧」这类命名，版本信息交给 git 与发布记录。

一个仓库的顶层结构固定：源码在 `src/`，静态资源在 `public/`，文档在 `docs/`，脚本在 `scripts/`。临时产物写 `.tmp_data/`，不进 git。

## 变量与函数命名

规律英文，可用下划线小写或 camelCase，同一个文件内保持一致，不混着用。名字必须是正面陈述，「不显示」写成 `hidden`，不写成 `notShow` 或 `noVisible`。

布尔量用 `is` `has` `can` 开头。函数用动词开头：`renderNav` `checkLogin` `buildSprite`。

## 样式类

见 `02-css.md`，核心是 `vz-` 前缀归组件、站点短名归布局、`vz-u-` 归工具类。

## 资源版本戳

这是当前最容易出问题的一处。有些站点靠 `app.js?v=20261015a` 这样的手写戳加一个版本常量，改完还要跑一次替换脚本同步到多个文件。跨站之后这套做法必然漏改，用户会拿到旧缓存。

改为内容哈希自动注入：构建或部署时对目标文件算 SHA-256 前八位，替换 HTML 与模板里的占位符。

```html
<script src="/vzuit.js?v={{HASH}}"></script>
```

`tools/stamp.mjs` 提供实现，接受站点根目录与占位符列表，扫描 HTML、TS 模板、JS 常量里的 `{{HASH:文件名}}` 并替换成真实值。手写日期戳的做法停止使用。

## 脚本边界

`vzuit.js` 现在是两件事混在一起：UI 运行时（弹窗、加载圈、页眉页脚渲染、图标工具）与站点业务（登录、验证码、公告、打赏、内容注入）。跨站复用时整套业务接口会被一起搬走，然后因为缺后端而报错。

规范要求按用途分层，同一份文件里用注释分节标清：

| 层 | 内容 | 能否跨站 |
|---|---|---|
| core | `escapeHtml` `inlineMd` `showLoading` `hideLoading` `VZAlert` `VZConfirm` `vzRenderShell` | 能，只依赖 DOM |
| site | 登录、TOTP、Turnstile、公告、打赏、内容注入 | 不能，依赖本站接口 |

新增函数必须落在其中一层，并在文件头部的分节注释里登记。跨站引用时只取 core 段，site 段各站自己写。这个拆分不做一次性重构，后续改造时按函数逐个搬。

## 注释

注释用中文。分节用「注释符 + 空格 + 标题」，例如 `/* 弹窗显隐 */`。不用减号或等号画横线做分隔。涉及取舍的注释要写清为什么这样做，不写「这里很复杂」这类无信息量的话。

## Python 与 Worker

Python 侧用 ruff 管格式与静态检查，行宽 100，命名 snake_case，公开函数带类型注解。Worker 侧（`functions/`）与前端共用 Biome，导出的 handler 用 `onRequest` 命名，路由常量集中在 `core/routes.ts`。

## 提交信息

格式 `[环境] 改了什么`，环境取 `[笔记本]` `[台式机]` `[VPS]`。一条提交只做一件事，不把格式化与功能改动混在一起，便于回滚。
