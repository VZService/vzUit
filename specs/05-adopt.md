# 05 · 接入与推进

## 三个阶段

第一阶段基座：补齐 token、规范、校验配置、sprite 与版本戳脚本。这一阶段只动基座仓本身。

第二阶段样板：拿一个自家小站完整接一遍，跑通「引 CDN、改类名、过 lint、截图比对」全流程，沉淀成接入清单。样板优先选没有历史包袱的新站。

2026-10-23 现状：自家现存的站要么是 fork（只引 token）、要么是上游镜像（不接）、要么没有图形界面（当不了样板），没有一个能完整走一遍。样板位先由基座仓自己填：`public/starter.html` 是一份可直接打开的最小接入示范，演示引用顺序、按钮与输入、开关与分段、弹窗与加载圈、文本与时间工具，以及由站点传数据渲染的页眉页脚。新站照它抄，不要从 CF_vzs 那种带全量业务的入口文件里剪。

第三阶段推广：按清单逐站接入，每站一次提交，不做跨仓批量替换。

## 接入判断

不追求把所有项目都改成同一套。判断依据是项目归属与维护关系，不是技术栈。

| 项目类型 | 结论 | 理由 |
|---|---|---|
| 标准源头站 | 持续演进，反向同步 | 规范从这里长出来 |
| 自家新站 | 接入，适合当样板 | 无历史包袱 |
| fork 自上游的项目 | 只引 token，不改组件 | 上游更新会与本地改动冲突 |
| 上游项目的镜像站 | 不接 | 样式跟上游走 |
| 委托方项目 | 暂不接入 | 见下节 |
| 单页作品 | 可选 | 视觉本身是内容，强套会破坏作品 |
| 机器人插件 | 不涉样式 | 面板由宿主程序渲染 |

## 委托方项目改动约定

凡受委托开发的项目，样式、结构、依赖的任何改动，动手前必须先征得委托方意见，得到明确答复再改。这条不因「顺手统一一下」「反正只是换个变量」这类理由放宽。

流程三步：先把改动范围、视觉影响、需要对方确认的点书面列清楚；对方同意后才动代码；改完回告实际改了什么、影响哪些页面。

规范对委托方项目只有建议权，没有直接落地权。

## 单站接入清单

1. 删掉站内重复的 reset 与手写变量块，改为引用 `tokens.css` 或 `vzuit.css`
2. 按 `01-token.md` 的替换表把硬编码色值、圆角、层级换成变量
3. 裸类名按 `02-css.md` 加前缀，先并列新名再迁用法，旧的留一版再删
4. `<img>` 图标改 `<use>` sprite，或退而求其次改内联
5. 手写版本戳改由 `tools/stamp.mjs` 注入
6. 跑 `npx @biomejs/biome check .`，格式与 lint 错误清零
7. 白色透明两步收编：`replace-hardcoded.mjs`（同值替换）→ `normalize-alpha.mjs`（夹值归并）
8. 启动本地预览，两档断点各截一张图，对比改前改后。截图前必须等 `document.fonts.ready` 并关掉动画与过渡，否则字体落地时机不同会让文字页整体抖动，比对结果全是噪声
9. 跑 `check-tokens.mjs <站点目录> --base src/tokens.css`，四项残留与漂移归零
10. 提交一次，提交信息写清改了哪一站

## 验收标准

改造完成的判定不是「规范写了」，而是这几条同时成立：`check-tokens.mjs --base` 报零残留、零漂移；类名全部带前缀；图标全部走 sprite 或内联；lint 零错误。

残留的两个例外要有注释兜底，不算违规：脚本里拼出来的内联样式字符串，以及 SVG 呈现属性上的字面色值（`var()` 在呈现属性里不生效）。第三方库的覆盖样式同样例外，但必须在规则上方注明出处。

像素比对的口径也要说清：同值替换必须零像素差；夹值归并允许差异，但差异得能追溯到档位收敛，且要留下比对数据（不同像素占比与最大通道差），不能只说「看起来一样」。

## 浅色主题的覆写方式

深色是默认。遇到本身是浅色的项目，用一层皮肤覆写 token，不覆写组件类。

```css
/* 浅色皮肤 */
:root {
  --vz-bg: #f4f6f9;
  --vz-deep: #edf0f4;
  --vz-bg-surface: #ffffff;
  --vz-bg-elevated: #ffffff;
  --vz-text: #1c2430;
  --vz-text-secondary: rgba(28,36,48,0.68);
  --vz-text-tertiary: rgba(28,36,48,0.52);
  --vz-border: rgba(28,36,48,0.12);
  --vz-primary: #2f5fd0;
  --vz-primary-gradient: linear-gradient(135deg, #2f5fd0, #1b3f9e);
  --vz-surface: rgba(28,36,48,0.03);
  --vz-shadow-card: 0 2px 12px rgba(28,36,48,0.08);
}
```

浅色下 `--vz-glass-*` 这组白色透明的语义会失效（叠在白底上看不见），改用 `--vz-surface` 配边框表达层次，不再使用 glass 系列。这条差异要写进该站自己的样式注释，避免后来的人照着深色站点的写法往上加玻璃效果。
